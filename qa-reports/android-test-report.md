## الأخطاء المكتشفة والمُصلَحة

### ✅ خطأ 1 — `req.body` يتسبب في crash عند الانضمام لمباراة (حرج)
**الملف:** `artifacts/api-server/src/routes/matches.ts`
**الخطأ:** `TypeError: Cannot read properties of undefined (reading 'position')`
**السبب:** عند إرسال طلب join بدون body (أو Content-Type خاطئ)، كانت `req.body` تساوي `undefined`، فيحدث crash.
**الإصلاح:** تغيير جميع `req.body as { ... }` إلى `(req.body ?? {}) as { ... }` في:
- `matches.ts`: join, create match, attendance, payment, rate (5 مواضع)
- `groups.ts`: create group, invite (2 مواضع)
**الحالة:** ✅ مُصلَح

### ✅ خطأ 2 — مسار `/notifications/mark-all-read` خاطئ (تحقق فقط)
**التفصيل:** Mobile app تستخدم `PATCH /notifications/read-all` وهو صحيح. خطأ في الاختبار اليدوي باستخدام `PUT` بدلاً من `PATCH`.
**الحالة:** ✅ لا يوجد خطأ في التطبيق — الـ API صحيح

## ملاحظات Android المحددة

### ✅ سلوك صحيح
- **RTL Layout**: الشاشات تعمل بـ RTL كاملة — نصوص، أزرار، ترتيب التبويبات
- **Cairo Font**: الخط العربي يظهر صحيحاً في الـ web view
- **No Basketball**: لا كرة سلة في أي مكان (فلاتر، بطاقات الرياضة، إنشاء المجموعات)
- **Sport Filters**: كرة القدم / بادل / تنس فقط
- **GlassTabBar**: شريط التبويب العائم يظهر في الشاشة الرئيسية
- **Pull-to-refresh**: عمل بدون crash في الاستكشاف

### ⚠️ ملاحظة بيئة الاختبار
- **تسجيل الخروج**: `Alert.alert` في Expo Web لا يُظهر نافذة تأكيد قابلة للنقر بـ Playwright. هذا سلوك web-only وليس خطأ على Android الفعلي حيث تعمل `Alert.alert` Native بشكل صحيح.
