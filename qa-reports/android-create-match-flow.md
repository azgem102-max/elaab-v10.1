## الخطوة ١ — النوع (`currentStep === 0`)

### ١.١ — اختيار نوع الجلسة (مباراة / تمرين)
- **الحالة:** ✅ **يعمل**

- كلا الخيارين يظهران في بطاقتين منفصلتين مع تسطير بصري واضح للمختار
- يُرسل للـ API عبر حقل `sessionType` في `createMatch`

### ١.٢ — اختيار الخصوصية (عامة / خاصة)
- **الحالة:** ✅ **يعمل**
- `isPublic` يُحفظ بـ `true`/`false`
- عند اختيار "خاصة" تُمسح `selectedGroupId` تلقائياً عند العودة للعامة
- يُرسل للـ API عبر حقل `isPublic`

### ١.٣ — زر "التالي" قبل الاختيار الواعي
- **الحالة:** ⚠️ **خلل طفيف**
- `validateStep()` في الخطوة ٠ لا تحتوي على أي منطق تحقق (تعيد `true` دائماً في هذه الخطوة)
- المستخدم يمكنه الضغط "التالي" مباشرةً دون لمس أي خيار
- متطلب التحقق المكتوب في مواصفات المنتج: "زر التالي لا يعمل حتى يتم اختيار القيم"
- **التقييم:** هذا تعارض مع المواصفات — يجب الحصول على قرار تصميمي واضح: إما قبول القيم الافتراضية (مباراة + عامة) كاختيار صريح كافٍ، أو إضافة منطق يُلزم المستخدم بالنقر على أحد الخيارين على الأقل قبل التقدم.
- **الأولوية:** متوسطة — يؤثر على تجربة المستخدم وليس على سلامة البيانات.

- الوقت المحدد يُميَّز بصرياً بلون الرياضة

### ٣.٤ — حقل اسم الملعب (venue)
- **الحالة:** ✅ **يعمل**
- تحقق: رسالة خطأ عند الخروج من الحقل فارغاً
- اقتراحات تظهر أثناء الكتابة من `VENUES`

### ٣.٥ — حقل رابط موقع الملعب (الميزة الجديدة) ⭐

| السيناريو | المتوقع | الواقع | الحالة |
|-----------|---------|--------|--------|
| يظهر تحت حقل الملعب | نعم | نعم | ✅ |
| رابط صحيح `https://maps.google.com/...` | بدون خطأ | `isValidUrl()` يقبله | ✅ |
| رابط خاطئ `abc` | رسالة خطأ | "رابط غير صحيح، تأكد من أنه يبدأ بـ https://" | ✅ |
| حقل فارغ (اختياري) | بدون خطأ | `isValidUrl("")` يُعيد `true` | ✅ |
| يُرسل للـ API | كـ `location` | `venueUrl.trim() \|\| undefined` | ✅ |

- **ملاحظة دقيقة:** التحقق يستخدم `new URL(url)` وليس تعبيراً نصياً، مما يعني أن `http://` تُقبل أيضاً (وليس `https://` فقط كما توحي رسالة الخطأ). هذا ليس خللاً وظيفياً لكن الرسالة مُضلِّلة قليلاً.

### ٣.٦ — حقل الوصف (اختياري)
- **الحالة:** ✅ **يعمل**

- يُرسل للـ API كـ `description.trim() || undefined`

## الخطوة ٤ — الإعدادات (`currentStep === 3`)

### ٤.١ — حقل التكلفة (cost)
- **الحالة:** ✅ **يعمل**
- `keyboardType="numeric"` يمنع إدخال الحروف على الجوال
- تحقق: رفض القيم السالبة والنصوص غير الرقمية مع رسالة خطأ

### ٤.٢ — حقل مستوى اللاعب (skillLevel) 🔴 **خلل حرج**

- **الحالة:** 🔴 **غائب — خلل حرج في ثلاث طبقات**
- **التفاصيل:**

  **طبقة الواجهة (Frontend):**
  - `Match` interface في `AppContext.tsx` يحتوي على `skillLevel?: "beginner" | "intermediate" | "advanced" | null`
  - `create-match.tsx` لا يحتوي على أي `useState` أو UI لـ `skillLevel`
  - `handleCreate` لا يُرسل `skillLevel` ضمن بيانات `createMatch()`

  **طبقة السياق (AppContext):**
  - `createMatch` callback تستقبل `Omit<Match, "id" | "players" | "joinedByCurrentUser">`، أي أن `skillLevel` مدعوم في النوع، لكنه لن يُرسل من الشاشة
  - `updateMatch` callback في `AppContext.tsx` معرّفة بـ `data: { title? venue? location? date? time? cost? maxPlayers? description? }` — **`skillLevel` غير موجود في interface التحديث**

  **طبقة الـ API (Backend):**
  - مسار POST `/matches` في `artifacts/api-server/src/routes/matches.ts` (السطر 340):
    `const { title, sport, date, time, venue, location, maxPlayers, cost, isPublic, sessionType, matchFormat, invitedGroupId, description } = body;`
  - **`skillLevel` غير مُستخرج من `body` ولا يُحفظ في `db.insert(matchesTable)`**
  - مسار PATCH `/matches/:id` لا يدعم تحديث `skillLevel` أيضاً
  - الحقل موجود في الجدول ويُقرأ عند جلب المباريات، لكن لا توجد طريقة لكتابته أبداً

- **التأثير الكامل:** جميع المباريات تُنشأ بـ `skillLevel = null` ولا يمكن تعديلها، مما يُعطّل فلترة "مستوى اللاعب" في شاشتَي الاستكشاف (`explore.tsx`) والرئيسية (`index.tsx`)
- **الأولوية:** 🔴 حرجة

### ٤.٣ — المباراة الخاصة: خيار اختيار المجموعة
- **الحالة:** ✅ **يعمل**
- عند `!isPublic` تظهر قائمة مجموعات المستخدم (`myGroups`)
- إذا لم تكن هناك مجموعات تظهر رسالة توجيهية
- التحقق يمنع النشر بدون مجموعة للمباريات الخاصة

## تفاصيل المباراة (`match-details.tsx`)

### ٥.١ — عرض معلومات المباراة
- **الحالة:** ✅ **يعمل**

### ٥.٢ — زر "📍 افتح الموقع" شرطي

| الحالة | المتوقع | الواقع | النتيجة |
|--------|---------|--------|---------|
| `match.location` موجود | الزر يظهر | `{match.location ? <SurfaceCard>...<Pressable>...` | ✅ |
| `match.location` فارغ/null | الزر لا يظهر | البلوك لا يُعرض | ✅ |

- **ملاحظة:** في بطاقة المعلومات العلوية (Hero) أيضاً: عند وجود location يظهر أيقونة `map-outline` صغيرة بجانب اسم الملعب، وعند النقر يُفتح الرابط — **لكن** هذا الزر يظهر دائماً (بطاقة الملعب في الـ Hero)، وعند عدم وجود location يستمر في الظهور ولكن `onPress` لا تفعل شيئاً (لأن `if (match.location) Linking.openURL(...)` موجودة).

### ٥.٣ — النقر على زر الموقع يفتح الرابط خارجياً
- **الحالة:** ✅ **يعمل**

## تعديل المباراة (`edit-match.tsx`)

### ٦.١ — تحميل بيانات المباراة الحالية
- **الحالة:** ✅ **يعمل**
- جميع الحقول تُهيَّأ من `match` الموجود:
  - `title`, `venue`, `location` (venueUrl), `cost`, `description`, `time`
- التاريخ يُحوَّل من نص إلى مؤشر في الـ 14 يوماً (`getInitialDateIndex`)
- إذا كان التاريخ خارج النطاق تظهر لافتة "التاريخ الحالي: ... اختر تاريخاً جديداً"

### ٦.٢ — حقل رابط الموقع يُحمّل الرابط الموجود
- **الحالة:** ✅ **يعمل**
- `const [venueUrl, setVenueUrl] = useState(match?.location ?? "")` — يُحمَّل الرابط مباشرة

### ٦.٣ — تعديل الرابط أو مسحه يُحفظ
- **الحالة:** ✅ **يعمل**
- `updateMatch` يُرسل `location: venueUrl.trim() || undefined`
- عند المسح (`venueUrl === ""`) يُرسل `undefined` مما يُزيل الرابط

### ٦.٤ — رسائل الخطأ للحقول غير الصحيحة
- **الحالة:** ✅ **يعمل بشكل جيد**
- تحقق من العنوان، الملعب، التكلفة، ورابط الموقع
- رسائل الخطأ تظهر تحت كل حقل

### ٦.٥ — skillLevel غائب من التعديل أيضاً
- **الحالة:** ⚠️ **ملاحظة**
- `updateMatch` في `AppContext` لا يدعم تعديل `skillLevel` (غير موجود في interface التحديث)
- يتوقع إصلاح هذا بالتوازي مع إصلاح الخلل في الخطوة ٤
